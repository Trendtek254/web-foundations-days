Day 8 — Reflection

The most difficult concept in this course was system design, especially understanding how different components work together when an application experiences heavy traffic. Concepts such as load balancing, caching, database transactions, and horizontal scaling initially seemed complicated because each solves a different problem. I overcame this difficulty by breaking the architecture into smaller parts, learning what each component does, and applying these concepts to practical scenarios. Designing TicketHub helped me understand why a system needs both scalable infrastructure and reliable database operations.

Based on the feedback I received during my capstone work, I would improve my technical documentation and make my design decisions more explicit. For example, working with a mock API such as JSONPlaceholder taught me that a successful simulated operation does not necessarily mean the server permanently changes its data. I would document these limitations clearly so other developers can distinguish mock-service behavior from frontend bugs. I would also improve my architecture diagrams and explain how database constraints prevent conflicting operations rather than simply listing technologies.

Next, I want to strengthen my understanding of SQL, REST APIs, database transactions, and Python backend development. I also want to build a small project that implements authentication, database persistence, and error handling. These skills will help me move from describing a system in a design document to building one that works reliably. My goal is to keep learning consistently while balancing my technical studies with nursing school.
